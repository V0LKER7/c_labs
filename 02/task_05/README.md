# Задание 5. overfprintf и oversprintf

## Условие
Аналоги fprintf и sprintf с дополнительными флагами:
- %Ro римская запись int
- %Zr цекендорфово представление unsigned int (от младшего разряда к старшему, в конце дополнительная 1)
- %Cv и %CV int в системе с основанием (параметры: число, основание; основание вне [2..36] заменяется на 10; буквы строчные или заглавные)
- %to и %TO строка в системе с основанием в десятичное число (параметры: строка, основание)
- %mi, %mu, %md, %mf дамп памяти (двоично, по байтам через пробел) для int, unsigned int, double, float

## Алгоритм
- Вывод накапливается в динамическом буфере (Buffer), потом пишется в поток или копируется в строку.
- process_format идёт по формату, handle_specifier проверяет два символа после % на кастомные флаги, иначе format_standard.
- format_standard разбирает флаги, ширину, точность (включая *), модификаторы длины и тип, берёт аргумент через va_arg нужного типа и форматирует через vsnprintf.
- Римские числа: жадно по таблице значений (диапазон от 1 до 3999, отрицательные с минусом, 0 и выход за диапазон дают ошибку).
- Цекендорф: жадно от большего числа Фибоначчи к меньшему, затем вывод от младшего и добавление 1. Для 0 печатается "01".
- Основание: деление с остатком, INT_MIN обрабатывается через long long.
- Дамп: байты в порядке памяти, биты от старшего к младшему.
- Возврат: число записанных символов или -1 при ошибке.

Сборка: `gcc -std=c99 -Wall -Wextra -pedantic -o main main.c -lm`

```
Ro: MCMXCIV IV MMMCMXCIX -XIV
Zr: 11 1011 100011 00101000011
Cv: ff -11111111 z 10
CV: FF 2N9C
to: 255 1295 5
mi: 00000101 00000000 00000000 00000000
mu: 11111111 11111111 11111111 11111111
md: 00000000 00000000 00000000 00000000 00000000 00000000 11110000 00111111
mf: 00000000 00000000 10000000 00111111

invalid base: 100
```

Вывод дампа соответствует little-endian платформе. Строка со стандартными спецификаторами ("[%5d] [%-5d] [%05.1f] [%s] [%c] [%x] [%ld] [%*d] [%%]") печатается так же, как стандартным printf.
